### 초기 실패 이력

처음 제한된 실행 환경에서는 네트워크 오류가 발생했다. 네트워크 접근을 허용한 초기 호출에서 두 검색 모두 403을 반환했다. 이 실패 기록은 한국 시각 **2026-10-22 00:46:14**, JSON의 UTC 기록은 `2026-10-21T15:46:14.008757+00:00`이다.

안전하게 요약한 오류:

```text
HTTP 403: 권한 또는 쿼터 제한 확인
(API 기능 비활성화 감지: 앱의 카카오맵/로컬 사용 설정 확인)
```

초기 실패는 `api_ok=false`, `selected_place_id=null`, `candidates=[]`였으며 `NOT_FOUND`가 아니었다. 현재 `results/kakao_local.json`(Git 제외)은 재실행 성공 결과로 갱신되어 `api_ok=true`와 실제 후보를 포함한다. API 키와 인증 헤더는 기록하지 않았다. 사용자가 외부 앱 설정을 완료한 뒤 성공했다.

## 실행 방법

Python 3.10 이상, 추가 패키지 설치 없음. 루트 `.env`에 다음 변수를 추가하거나 프로세스 환경변수를 사용한다. 기존 YouTube 키는 유지한다.

```dotenv
KAKAO_REST_API_KEY=발급받은_REST_API_키
```

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python kakao_local_poc.py --output results/kakao_local.json

# 별도 식당을 검사하려면 이름과 주소를 함께 지정
python kakao_local_poc.py --name '뽀요베리' --address '서울 마포구 월드컵로13길 55-15'

# 모의 테스트만 실행 (네트워크·실제 키 불필요)
python -m unittest -v test_kakao_local_poc

# 기존 YouTube 테스트 포함
python -m unittest -v
```

`KAKAO_REST_API_KEY` 프로세스 환경변수가 `.env`보다 우선한다. `.env`는 스크립트와 같은 디렉터리에서 읽고, 단순 `이름=값` 및 따옴표만 지원한다. 변수 치환·셸 코드 실행·인라인 주석은 지원하지 않는다. `.env.example`에는 자리표시자만 추가했다. 실제 키는 소스·문서·결과 파일에 넣지 않는다.

종료 코드: 정상 검색은 0(검토 필요/빈 검색도 포함), 키·API·저장 실패는 1, 잘못된 CLI 인자는 2. API 실패 시에도 다른 식당의 검색은 진행하고 전체 결과를 출력한다.

## 검색 및 출력

`GET https://dapi.kakao.com/v2/local/search/keyword.json`을 사용한다. 식당명만 `query`에 넣고 정확도순으로 페이지당 15개를 요청한다. 지역·음식점 카테고리 제한은 두지 않아 다른 지점도 후보에 남긴다. 인증은 메모리 내 `Authorization: KakaoAK …` 헤더로만 전달한다.

최대 3페이지(노출 가능 후보 45개)를 순회하며 ID로 중복을 제거한다. 모든 확보 후보에 장소 ID `id`, 상호 `place_name`, 도로명 `road_address_name`, 지번 `address_name`, 경도 `x`, 위도 `y`, 카카오맵 링크 `place_url`을 출력한다. 검색 전체 건수·확보 건수·요청 페이지 수·완전성도 출력한다. 전체 결과가 노출 한도를 넘거나 끝 페이지에서도 건수가 부족하면 유일성을 증명할 수 없어 자동 확정하지 않는다.

## 매칭 규칙과 한계

1. 이름: NFKC 정규화, 영문 소문자화, 공백·기호 제거 후 비교한다. 정규화 이름 일치 또는 `상호+지점명+점` 형태만 강한 이름 일치로 인정한다. 지점명은 원문 출력에 유지한다.
2. 주소: 현재 실험 범위인 서울 주소에서 `서울/서울시/서울특별시`를 통일하고, 구·도로명(또는 동/가)·본번과 부번을 파싱해 비교한다. `55`, `55-15`, `55-16`을 서로 다른 주소로 취급한다. 입력과 후보의 도로명 또는 지번 주소 중 하나가 같은 상세 주소 키를 가져야 한다.
3. `MATCHED`: 이름과 주소가 모두 강하게 일치하는 후보가 정확히 하나이고 검색이 완전할 때만 부여한다. 같은 주소에 이름 유사도 0.7 이상인 다른 후보가 있으면 추가로 검토한다. 유사도만으로 확정하지 않는다.
4. `REVIEW_REQUIRED`: 주소 불일치·미지원 형식·도로명 부재로 대조 불가·복수 유력 후보·불완전 검색·API 실패. 선택 장소 ID는 비워 둔다.
5. `NOT_FOUND`: 완전한 정상 검색 결과에 후보가 없을 때. 미등록·검색어 차이 가능성이 있으므로 수동 확인이 필요하다.

도로명 주소가 없는데 입력이 도로명이고 결과는 지번이면 변환을 추측하지 않는다. 입력도 지번이고 상세 키가 일치하면 비교할 수 있다. 층·호 정보가 붙은 주소, 서울 밖 주소, 상호 오탈자·별칭은 보수적으로 검토 대상으로 남긴다. 같은 건물의 여러 업장이나 숫자를 포함하는 지점명 등에 대한 고도화는 미구현이다. `MATCHED`는 이 PoC 규칙 안의 일치이며 실제 영업 여부나 식당 자동 등록 승인을 뜻하지 않는다.

## 오류 처리와 검증

HTTP 401 인증 실패, 403 권한/쿼터, 429 호출 한도, 기타 HTTP 오류, 네트워크·20초 타임아웃, 잘못된 JSON, 응답 구조·필드·좌표 오류를 처리한다. 서버의 임의 메시지를 그대로 출력하지 않고 고정된 안내 문구로 분류한다. 비활성화·쿼터 표현 감지는 원인을 좁히는 보조 진단이며 외부 앱 설정을 직접 확인한 것은 아니다.

**2026-10-22 재실행: Kakao 단위 테스트 21개, 기존 YouTube 9개를 포함해 총 30개 통과(실패 0개).** `python -m unittest -v`로 검증했다. 이 30개는 모의 응답/로컬 로직 검증이며 위의 실제 API 성공 기록과 구분한다.

| 테스트 범위 | 모의 검증 결과 |
| --- | --- |

| 인증/권한/할당량/네트워크/잘못된 JSON/응답 필드 오류 | 안전한 오류·키 비노출 |

| CLI API 실패 및 비활성화 진단 | api_ok=false, REVIEW_REQUIRED |

## 다음 PoC 과제

- 실제 후보·ID·좌표 확보 재검증은 완료했다. 이어 첫 기능의 관리자 검토→승인→DB 저장 흐름을 구축한다.

- 동명 식당·여러 지점·상호 변경·이전 사례를 늘려 오탐과 누락률을 평가한다.
